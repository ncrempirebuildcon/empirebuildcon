### How the CMS screens work

- **Session:** every CMS page calls `requireSessionUser()` (`src/lib/session.ts`) on the server, then renders `AdminShell` around a client screen. The shell shares the user and permissions through `useAdminSession()`; menu items and buttons a role can't use are hidden, and the API checks every call anyway.
- **API calls:** only through the generated client (`@empire/api-client`) via `call()` in `src/lib/api.ts`, which returns the data or throws `ProblemError`, and sends the user to sign in on a 401. Writes carry the CSRF token the shell sets from `/auth/me`. Types come from `Schema<"ProjectAdmin">` and friends, never hand-written.
- **Errors:** `src/lib/problems.ts` turns problem+json into a page message and field messages keyed by the dotted field path (`price.min_inr`), shown next to their fields.
- **Saving in the editor:** the project's own fields save together with "Save draft" (PATCH); fields typed while a save runs keep the newer text and stay unsaved. Towers, configurations, specifications, location advantages, construction updates and payment plans save item by item (add, edit, remove, Move up/Move down); an item form is locked while it saves, and opening another item while one has unsaved edits asks "Discard your changes?". Amenities save with "Save amenities".
- **Unsaved changes:** leaving by a link, closing the tab or signing out asks first (`useUnsavedChanges`); Publish and Duplicate wait until the changes are saved.
- **Off market on a live project:** without `projects.publish`, a published project can't be moved into or out of "Off market" (the API refuses it too), and the Sales status field says why.
- **Map pin:** "Get pin" stores the normalised plus code from the API (never the place name typed after it) and the link only when a link was pasted; both are shown with Clear buttons, and typing coordinates by hand clears them.
- **Phones:** no CMS page scrolls sideways at 390 px; wide tables scroll inside their own region (`qa/specs/responsive-cms.spec.ts`, `responsive-content.spec.ts`).
- **Media manager** (`src/components/admin/media/`, `src/lib/media/`, ARCHITECTURE §12):
  - One drop zone (a real button with a file chooser; dropping files is a bonus) sends each file to the right list by type: photos to the gallery, videos, documents. Photos, Videos and Documents show their counts; each item has its order number, the cover star (photos), a HIDDEN badge, its honest label (artist's impression / actual photo / progress photo with the month), a "Show on website" switch, Move up/Move down (mouse users can also drag), "Edit details" (title, alt text, label and month, in a dialog) and "Remove from project" (the file stays in the library).
  - **Honest labels first:** photos dropped on the Media tab wait for one question, "What are these photos?" (artist's impression, actual photo, or progress photo with its month; nothing pre-selected). The answer is sent with the batch (`ImageUpload.label`/`label_month`), so they arrive shown. The API keeps an unlabelled gallery photo hidden: such a photo says "Hidden until labelled", its switch is disabled with the reason, and "Add label" opens its details. Progress photos added to a construction update are labelled with the update's month.
  - Files are checked in the browser before anything is sent (`lib/media/files.ts`: JPG, PNG, WebP, AVIF ≤ 10 MB; MP4, MOV, WebM ≤ 100 MB; PDF, DOC, DOCX, PPT, PPTX ≤ 10 MB; never SVG, HEIC or GIF). The API checks everything again.
  - **Photos** are re-encoded in the browser (`lib/media/resize.ts`), which also drops EXIF/GPS data, then sent to `POST /admin/media/images` with an XHR so progress shows: photos at a 2560 px long edge as WebP (else JPEG) at 0.85; the RERA QR as lossless PNG at 1200 px; floor plans as lossless WebP (else PNG). Smaller sizes are tried when a result is over 10 MB.
  - **Videos and documents** go straight to the store: `upload-signature` → XHR POST of the file with exactly the signed `fields` to `upload_url` → `confirm` with the store's reply unmodified (it attaches the file too). In development and tests the API's fake store answers like Cloudinary on `/api/v1/dev-media/…`, so the same code runs.
  - Uploads run one at a time with a progress bar (`role="progressbar"`), Cancel while the file is being sent, and Dismiss for a refusal; start, finish and failures are announced in a polite live region. Once every byte is sent the row says "Saving…" and Cancel goes away (the server finishes on its own); a Cancel that races the end re-reads the owner, so the list shows what was really saved. Running uploads count as unsaved changes for the leave warning; editing a construction update keeps its photo uploads running.
  - "Show on website" and the cover star save one change at a time: a switch flipped while another saves shows "Saving…" and waits its turn.
  - Single places replace in one step: the RERA QR code (Documents; required to publish; a live project's QR can be replaced, never removed or hidden), the brochure (one PDF), each configuration's floor plan (image or PDF), the share image (SEO; pick a project photo or upload one, saved with Save draft as `seo.og_image_id`).
  - Media needs `media.upload`, not `projects.write` (marketing manages media without editing facts); deleting from the library needs `media.manage`.
  - Previews use plain `<img>` with the store's thumbnail URLs and the item's alt text (else its title); QR codes and floor plans sit on an ivory tile. The public image loader comes in Phase 5 (`TODO(phase-5)`).
- **Request size:** `next.config.ts` lets the `/api` proxy pass request bodies up to the API's 10 MB photo cap plus 64 KB (`experimental.proxyClientMaxBodySize`); without it Next.js cuts bodies at 10 MB. With the fake store, direct uploads also pass through this proxy, so locally a video above about 10 MB is refused; test big files against Cloudinary.
- **Map:** the draggable map comes with the public site (`TODO(phase-5)`).
- **Leads** (`src/app/admin/leads/`, `src/components/admin/leads/`, `src/lib/leads/`, ARCHITECTURE §8):
  - The shell loads `GET /admin/dashboard` once per page: the **Leads** menu item shows the unread count as a badge ("12 unread" for screen readers) and the dashboard reads the same answer (`useAdminSession().dashboard`). Opening a lead refreshes it.
  - **Object-level rule:** a sales user (no `leads.read_all`) gets only their own leads from the API; the inbox hides the Owner filter and Mine/Unassigned for them, and someone else's lead shows "This lead isn't available" (the API answers 404, like a missing lead).
  - **Phones in lists are masked** (`maskPhone`, `+91 98xxxxxx10`); the full number appears only on the lead detail and in the selected visit's Call/WhatsApp links. The lead page's browser title is "Lead", never the person's name.
  - **Pipeline:** stage changes are toggle buttons on the detail and a "Move to" list on each board card (keyboard and screen-reader friendly; no drag). Lost always asks for a reason. Moves are announced in a polite live region; on the board focus follows the moved card.
  - **Consent:** a manual lead needs a consent note ("Verbal on phone call"); the consent record is read-only. Marketing consent is shown as given or not given, never assumed.
  - **Export:** fetched with the session cookie and the CSRF token (the API refuses the export without it, so a plain link can't download personal data), turned into a temporary object URL and saved with `<a download>` (the URL is revoked afterwards); a refusal (over 50,000 rows, no permission) shows the API's message in the dialog.
  - **Unsaved work:** a typed note, open "Edit details", a chosen stage, an edited visit and the Add lead form count as unsaved changes (`useUnsavedChanges`; one guard per screen, fed by `useDirtyParts`). Links, sign-out, closing the tab, "Mark unread" (through `leave()`) and moving the calendar ask first; Cancel in Add lead asks "Discard this lead?".
  - **Duplicates:** the duplicate check and the timeline show only leads the viewer may open (the API leaves the others out); a viewer without `leads.read_all` never sees a claim about leads outside their own.
  - **Erase:** the ConfirmDialog says which leads it erases (the lead and its repeat enquiries; optionally every lead with the phone number), lists what is removed (name, mobile, email, message, preferred contact time, page addresses, click IDs, UTM term and content, note texts, the lost-reason note, visit notes) and kept (reference, stage history, source and campaign, project, consent metadata), says it can't be undone, and focuses "Keep the data" first.
  - **Times:** stored in UTC, shown and typed in India time (`@empire/ui/format`: `istDate`, `istTime`, `istToIso`, `startOfWeek`, `formatAge`). A confirmed visit's time is sent as one UTC instant.
  - Staff to assign or to handle a visit come from `GET /admin/lead-owners`.

- **Content** (`src/app/admin/pages/`, `posts/`, `offers/`, `faqs/`, `testimonials/`, `redirects/`, `src/components/admin/content/`, `src/lib/content/`, ARCHITECTURE §6 and §16):
  - **Menu:** "Pages" opens `/admin/pages`; "Offers & blog" opens the first section the role can use (Offers needs `offers.manage`, Blog posts, FAQs and Testimonials `content.read`, Redirects `seo.manage`; `CONTENT_SECTIONS` in `src/lib/routes.ts`). Each section shows the same sub-navigation (links with `aria-current`, not ARIA tabs, because each section is its own address).
  - **Blocks:** the editor keeps the whole ordered list and sends it in one `PUT /pages/{id}/blocks`. Each type has its own form (`blocks/ContentForms.tsx`, `blocks/ReferenceForms.tsx`) typed from the API's `BlockInput` union. Before saving, `checkBlock` repeats the rules staff hit most: a heading where required, a number's **source and "true as of" date** (COMPLIANCE), a safe button link (a path starting with `/` or `https://`; `javascript:` and the like refused, `lib/content/links.ts`). API errors (`blocks.3.data.items.0.source`) land on the same fields. Moves, adds, deletes and show/hide are announced in a polite live region; focus stays on the control used, and after "+ Add block" it moves to the new block's settings heading.
  - **Media fields** (`components/admin/media/MediaField.tsx`, `LibraryPicker.tsx`): "Choose from the library" (a dialog of library photos or videos with search, as native radio buttons or checkboxes) or "Upload a photo" straight into the library (part 2's SlotUploader, no attach target). The page's blocks name library ids; their thumbnails come from `Page.media`. Galleries take up to 24 photos in your order.
  - **Honest labels** (COMPLIANCE, DESIGN_SYSTEM §7): photos the website shows with their label (hero, image and gallery blocks, post covers, offer images; `labelRequired`) ask "What is this photo?" before they upload (PhotoLabelDialog, nothing pre-selected), and a library photo without a label opens its details to add one before it is used (needs `media.upload`; without it the field says who can label it). Sample tiles and testimonial photos (a person, not a property) are exempt, as in the API.
  - **Formatted text:** body text, answers and columns use `FormattedTextEditor` from `@empire/ui` (hint, count, live preview drawn by the same safe `FormattedText` renderer the website will use). Raw HTML is never rendered.
  - **Permissions mirrored from the API:** scheduling and archiving a live page need the publish permission; a legal page (publish, unpublish, schedule, archive, delete, any change while live or scheduled, kind to or from legal) needs `legal.publish` (`lib/content/pages.ts`); the offer-banner block's "One offer" choice and its "Manage offers" link need `offers.manage` (others keep an existing choice, shown read-only as "Offer chosen by an offers manager"); SEO fields need `seo.manage`; showing a FAQ needs `content.publish`; testimonials need `content.publish` to write. The API checks all of them.
  - **Honesty:** the offer form repeats the API's light wording checks (`lib/content/offers.ts`: pressure words refused; a price or discount needs a terms line or link); no countdown field exists. Testimonials can't be shown without a source and consent date. Placeholders in forms use `[brackets]`.
  - **Where a file is used:** the media library's "Used in N places" opens a list from `GET /admin/media/{id}/usage` with links to each project, page, post, offer or testimonial (a testimonial is named by the buyer's initials only).
  - **Long lists:** offers, testimonials and redirects page 25 at a time (`Pager`, `?page=` in the address); a just-saved item stays open in its editor even when it sorts onto another page.

- **Sign-in, settings and users** (Phase 4 part 5; `src/app/admin/login/`, `forgot/`, `setup/`, `reset/`, `account/`, `users/`, `settings/`, `audit/`, `src/components/admin/auth/`, `src/lib/auth/links.ts`, SECURITY.md §1):
  - **Two steps at sign-in:** `POST /auth/login` answers 200 (signed in) or 202 with `{step: "verify" | "setup"}` and a 5-minute HttpOnly `__Host-empire_2fa` cookie; no session exists until the second step succeeds (`/auth/2fa/verify`, or `/auth/2fa/enrol` + `/enrol/confirm`). Wrong codes count toward the same lockout as passwords; a timed-out step returns to the password form with the API's sentence.
  - **Recovery codes are shown once:** once a code confirms two-factor, Back (sign-in) and Cancel (My account) go away; the only way on is "I've saved them" (copy and download stay), and My account reads `me` again at once, so the status can't go stale.
  - **Secrets on screen:** the two-factor key, its QR code (an SVG data URL from the API, shown only if it is one) and recovery codes live only in component memory while their step is open; they are never logged, stored in the browser, put in the address or a title, and the API never returns them again. The recovery codes' text file is made in memory and its object URL revoked at once. Recovery codes are spelled out for screen readers (`CodeList`).
  - **Links with tokens:** `/admin/setup` and `/admin/reset` are loaded in the browser only (`next/dynamic` with `ssr: false`), read the token once from the URL fragment (never sent to the web host, so it can't reach its request logs; `?token=` is read as a fallback for older emails), remove it from the address with `history.replaceState` straight away, and send it only in the request body. A reload shows "This link is incomplete".
  - **Settings sections** (`settings/sections.ts`, `fields.ts`, `GroupForm.tsx`): every section is drawn once and kept, so switching sections never loses typing; each saves only its changed groups with one `PATCH /admin/settings/{group}` each and shows the API's messages at the fields. Text is trimmed before saving, except fields marked `keepSpaces` (the title ending " · Empire" keeps its leading space). The permission shown ("Needs …") and the read-only state come from `canSaveSection`; the retention period needs the super-admin (COMPLIANCE). The API checks everything again.
  - **Users:** your own account's role, sessions and two-factor aren't offered in the panel (change them on My account or ask another super-admin), so a slip can't lock you out mid-task. The API refuses demoting or deactivating the last usable super-admin; its sentence is shown as it comes.
  - **Audit log:** read only. Before/after lines come from the entry's `changes` (`lib/audit.ts`). Each row's chip shows the board's kind (Login, Publish, Update, Export, Permission, Erasure, mapped in `auditKind`); the action filters are queries the API answers on the server (`action_prefix` such as `auth.` or `user.`, or an exact action such as `lead.exported`), so counts and pages stay honest. The Person list is every account for the super-admin and the people who can own leads for admins (the only staff list their role may read), plus "System".
  - **Downloads pass the leave warning:** `useUnsavedChanges` ignores `<a download>` and blob:, mailto: and tel: links, which don't leave the page (the recovery codes' text file is downloaded while the codes count as unsaved).
  - Unit tests in `test/` cover the link rules (`auth-links.test.ts`), the audit wording (`audit.test.ts`) and the users screen's rules (`users.test.ts`).

## How it fits together

- The browser only calls `/api/*` on this site; `next.config.ts` rewrites those calls to `API_ORIGIN` (handbook/ARCHITECTURE.md §3). `skipTrailingSlashRedirect` stays on (`DO NOT CHANGE`).
- Security headers are set in `next.config.ts` (handbook/SECURITY.md §4). The nonce-based CSP comes in Phase 5.
- CMS pages check the session on the server (`src/lib/session.ts`) and are never cached.
- Styling uses only the generated tokens from `@empire/ui` (`bg-noir-900`, `text-gold-300`, `rounded-card`, `font-display`…). Fonts are self-hosted from npm (`@fontsource`).

## Rules

- **Tokens only:** never hard-code a colour, radius or font that has a token.
- **No facts in code:** prices, RERA numbers, counts and company details come from the API/CMS. Unknown facts are `[placeholders]`.
- **Accessibility (WCAG 2.1 AA):** real buttons and links, a visible label on every field, a focus ring, 44 px touch targets, and text on every status. Reordering always has Move up/Move down buttons; confirmations use `ConfirmDialog`, never `confirm()`. Links inside sentences are underlined.
- `dangerouslySetInnerHTML` is banned by lint except in `src/components/JsonLd.tsx` (`SECURITY`).
