## Goal

When the owner turns on the `chat_widget` flag, visitors see a small **Ask about our projects** button. It opens a panel where they type a question and get a short answer from Empire's own content, with links to the pages it came from. Booking a visit or a call always goes through the site's existing WhatsApp, Call and enquiry buttons, never through the chat.

With the flag off, as at launch, the widget renders nothing and none of its code loads.

## Scope

1. **Loading** (`apps/web/src/components/chat/ChatLauncher.tsx`, new):
   - In `(site)/layout.tsx`, render `<ChatLauncher />` only when `site.features?.chat_widget === true`.
   - `ChatLauncher` is a small client button, fixed bottom-right on desktop and above the mobile bar on phones, labelled **Ask about our projects**.
   - The panel's code (`ChatPanel.tsx`) is loaded with `next/dynamic` only when the button is first pressed, so the first page load has no chat code beyond the button.
2. **The panel** (`apps/web/src/components/chat/ChatPanel.tsx`, new):
   - **Shape:** a non-modal dialog (`role="dialog"`, `aria-modal="false"`, labelled by its heading) with a close button. The page behind it stays usable.
   - **Note:** a line under the heading: "[DRAFT] Answers come from an AI using Empire's published pages, and can be wrong. Please check the project page, and don't share personal details here."
   - **Input:** a text box (at most 500 characters, with a live count near the limit) and **Send**. Enter sends; Shift+Enter adds a new line.
   - **Messages:** the conversation as a list, with a polite live region that announces each new answer. While waiting, show "Looking that up…".
   - **Answers** are shown as **plain text only**.
     - Turn each `[n]` into a link to `citations[n-1].url`, labelled with its title. Nothing else in the answer becomes a link, HTML or Markdown.
     - Below the answer, list the citations as links.
   - **Cards:** for each entry in `cards`, show a small card with the project's name, its UP-RERA number and a link to the project. Take the data from the existing public project API (`/api/v1/public/projects/{slug}`), **never from the answer text**.
   - **Fallbacks:**
     - `no_answer`: "I couldn't find that in our pages."
     - `busy`: "The assistant is resting for today."
     - `429`: "You've asked a lot quickly. Please wait a minute."
     - Any network error: "Something went wrong."
     - Each one is followed by the WhatsApp, Call and **Request a call back** buttons. Request a call back scrolls to or opens the page's existing enquiry form, or goes to `/contact`.
   - **The same three buttons always sit at the bottom of the panel.**
   - **History:** only in React state, never stored. Send at most the last 2 turns as `history`. Closing the panel keeps the conversation until the page is left.
   - **Wording:** all of it in one exported `CHAT_COPY` constant, each string starting with `[DRAFT]`.
3. **API client** (`apps/web/src/lib/chat.ts`, new):
   - `askAssistant({ message, history, page })`. It posts to `/api/v1/ai/chat` with the CSRF and JSON conventions the other public posts use, and returns a typed union: `answer | no_answer | busy | rate_limited | error`.
   - It enforces the contract's limits before sending.
   - A 404 means the flag was switched off. Hide the launcher for the rest of the visit.
4. **A mock for development and tests:** a Playwright `route` that answers `/api/v1/ai/chat` in the specs. No dev-only route in the app.

**Out of scope:**
- the API;
- the knowledge index;
- the flag itself, which already exists;
- consent;
- any model or provider.

## Tests required

- **Vitest:**
  - `askAssistant`: one test for each reply type, for the limits, and for a 404 hiding the launcher.
  - `[n]` rendering: links only to the cited URL. An answer containing `<a href>`, `<img>` or Markdown is shown as plain text.
  - Fallbacks show the three buttons.
  - History sends at most 2 turns.
- **Playwright** (`qa/specs/chat-widget.spec.ts`):
  - **With today's flag off:** no launcher on `/`, `/projects` or a project page, and no request for chat code. This guards the launch state.
  - **With `/api/v1/public/site` routed so `features.chat_widget` is true, and `/api/v1/ai/chat` routed to answers you choose:**
    - open the panel, ask, see the answer with a working citation link and a project card;
    - see each fallback with its three buttons;
    - axe at 390 px and at desktop width;
    - the mobile bar's buttons stay clickable;
    - Escape closes the panel and focus goes back to the launcher.
  - If routing the public site isn't possible because the page renders on the server, say so in the report and use jsdom for those checks instead. Claude adds the end-to-end run in 7.2.
- **Failure proofs:** stub the behaviour (not the file) and show the specific tests failing, then passing.
