## Goal

The frame every public page sits in, wired to the public API from 5.1, safe and observable. When this is done, a visitor at `/` sees the real header, menu, footer and mobile action bar driven by CMS data, the site refreshes within seconds when staff publish something, images come through Cloudinary at the right size, a strict Content-Security-Policy protects every page, and errors reach Sentry. The actual project, content and form pages come in 5.3–5.5; this task builds what they all share. It also closes the follow-ups left from 5.1 (Part B).

## Scope · Part A: website shell (`apps/web`, `packages/ui`, `apps/api` for revalidation)

1. **Public route group.** Put public pages under their own route group (for example `app/(site)/`) with its own layout, separate from `/admin`. The CMS keeps its current layout and `no-store` caching. `/` keeps its current holding content inside the new shell until 5.5 builds the home page, but the header, footer and bar are real.
2. **Server-side data layer** (`lib/public/…`, server-only):
   - Typed calls to the 5.1 endpoints through the generated client, sending the edge key and, when there is a visitor request, the visitor's IP (`lib/edge.ts`). Server renders without a visitor use the API's server bucket (D-038).
   - Next.js caching by tag (`site`, `project:<slug>`, `projects`, `properties`, `page:<slug>`, `posts`, `post:<slug>`, `faqs`, `testimonials`, `redirects`) plus the 1-hour safety revalidate (ARCHITECTURE §5).
   - Errors: a 404 from the API becomes `notFound()`; other failures show the error page, never a half-rendered page with invented data.
3. **Revalidation, end to end:**
   - Web: `POST /_internal/revalidate` (outside `/api/*`, so the proxy never forwards it) that accepts a JSON list of tags, verifies an HMAC-SHA256 signature over the body and a timestamp with `REVALIDATE_SECRET` (constant-time compare, 5-minute window, replay refused), and calls `revalidateTag` for each. Anything unsigned or stale gets 401 with no detail.
   - API: an outbox handler (`integrations/handlers.py`, replacing the `TODO(phase-5)`) that maps publish events (`project.*`, `configuration.changed`, `construction_update.published`, `media.*` on live owners, `page.*`, `post.*`, `faq.changed`, `testimonial.changed`, `offer.*`, `settings.updated`, `flag.changed`, `redirect.changed`, `consent_text.published`) to tags and calls the web app with the signed request. Idempotent; retried by the outbox on failure; no personal data in the call. New settings: `WEB_REVALIDATE_URL` (and `REVALIDATE_SECRET`, which exists) in `.env.example`, required in staging and production.
4. **Shell components** following the boards and `DESIGN_SYSTEM`:
   - Header: logo (from `brand/`), navigation from `/public/site` (pages with `show_in_nav`, in order, plus Projects), a "Book a site visit" or "Enquire" button that goes to the contact page for now, skip link, keyboard-usable menu, mobile menu (a real `<button>` with `aria-expanded`, focus trapped while open, Escape closes).
   - Footer: company name, addresses, contact numbers and emails from settings (hidden when they are placeholders in production, per D-038), social links, the regulator line (UP-RERA and up-rera.in), links to the legal pages, and "© year Empire". Nothing invented.
   - Mobile action bar (phones only): Call and WhatsApp with equal weight (DESIGN_SYSTEM), using the settings' numbers and the WhatsApp opening message with `{page}` replaced by the current path; hidden when the numbers aren't set.
   - Active offer banner (`placement = banner`) from `/public/site`, if any: a plain, dismissible strip with the offer's terms line. No countdown or urgency (D-035).
   - SAMPLE marker: in development and staging, a visible "Sample data" ribbon when the page shows sample items (never in production, because the API never returns them there).
5. **Images:** a custom `next/image` loader for Cloudinary (`res.cloudinary.com`) that builds `f_auto,q_auto,w_<width>` URLs from the API's delivery URLs, with `sizes` guidance in a small `PublicImage` component that always passes the alt text and shows the honest label where the design calls for it (D-033). The fake media store's URLs keep working in development and tests.
6. **Content-Security-Policy** (SECURITY §4, `TODO(phase-5)` in `next.config.ts`):
   - Nonce-based `script-src` set per request in `proxy.ts` (extend its matcher to pages; keep the `/api` behaviour exactly as it is: it is `DO NOT CHANGE` code, so any change to it needs the owner's approval in the PR).
   - `img-src 'self' https://res.cloudinary.com data:` (plus the map tile host only when 5.3 adds the map), `connect-src 'self' https://api.cloudinary.com` (the CMS uploads), `frame-ancestors 'none'`, `form-action 'self'`, `object-src 'none'`, `base-uri 'self'`, and Sentry's ingest host if Sentry is on.
   - **Report-only** by default, switched to enforcing with an environment variable (`CSP_ENFORCE=true`), so staging runs report-only for a week first. The CMS must keep working under the enforced policy: the browser suite runs with it enforced.
7. **Sentry for the web app** (`TODO(phase-5)` in `app/error.tsx`): `@sentry/nextjs` with `NEXT_PUBLIC_SENTRY_DSN` (empty = off, which is the default locally and in CI). Before sending: drop query strings and fragments from every URL (lead search and setup links can carry personal data or tokens), no request bodies, no cookies, no user IP; low sample rates. Check the current version on npm and give the date (11.10.0 was the latest on 1 Nov 2026).
8. **404 and error pages** following `Noir404`: on-brand, with links to Projects, Contact and home; the 404 keeps `noindex`. The site-wide `robots` stays `noindex` until go-live (Phase 9).
9. **Accessibility and performance:** skip link, landmarks, visible focus, 44 px targets, no sideways scroll at 390 px, colour never the only signal. The shell adds no client JavaScript beyond the menu, the offer dismiss and Sentry; everything else is server-rendered.

## Rules for this task

- `proxy.ts` and `lib/edge.ts` carry `SECURITY`/`DO NOT CHANGE` notes: extend them only as described in Scope 6, keep every existing behaviour and test, and list the change under "Needs owner approval" in the PR text.
- No third-party requests from public pages except Cloudinary images and (when on) Sentry. Fonts stay self-hosted (`@fontsource`, already in place).
- New dependencies: `@sentry/nextjs` only. Check its version and date on npm; pin it.
- Browser suite budget: 6 sign-ins per run; this task adds none. Public pages need no sign-in.
- Ask for every command's permission once at the start (see the prompt).

## Tests required

- **Web unit tests:** the revalidate route (good signature, bad signature, stale timestamp, replay, wrong method); the Cloudinary loader (widths, transformations, non-Cloudinary URLs left alone); the WhatsApp link (`{page}` replaced, numbers formatted); footer and bar hide placeholders and missing numbers; Sentry `beforeSend` strips query strings, fragments, bodies and cookies.
- **API tests:** the revalidation handler maps each event type to the right tags, signs correctly, is idempotent and retries on failure; every Part B item.
- **Browser tests:** the shell on desktop and 390 px (header, menu open/close by keyboard, footer, mobile bar), the 404 page, axe on each, CSP enforced with no console violations on the public shell **and** on the main CMS screens, and a publish in the CMS that changes the footer or nav after revalidation.
