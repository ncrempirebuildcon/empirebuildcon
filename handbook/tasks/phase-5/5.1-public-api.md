## Goal

Every read-only endpoint the public website needs, under `/api/v1/public/*`, returning only published, public data in shapes made for the site. No web pages in this task: the website starts in 5.2. When this is done, a developer can build any public page with one or two API calls, and nothing private (staff fields, personal data, drafts, sample data in production) can leak through these endpoints.

## Scope

1. **Visibility rules, in one place** (a small `public` helper used by every endpoint):
   - Only `publish_state = published`. Projects and configurations with `sales_status = off_market` never appear; `sold_out` appear after available ones with their status (ARCHITECTURE §7).
   - **Sample data (D-015):** when `APP_ENV` is `production`, rows with `is_sample = true` are never returned, anywhere (including inside page blocks, grids, sitemaps and counts). In development, test and staging they are returned with `is_sample: true` so the site can mark them.
   - **Placeholders:** settings values that still hold a `[placeholder]` (text in square brackets) are returned as `null` in production, so the site hides them; elsewhere they are returned as they are.
   - Hidden media links, hidden blocks, hidden FAQs, testimonials that can't be shown, inactive or ended offers, and redirects that are switched off are never returned.
2. **`GET /public/site`** (`PublicSite`): company and contact details, social links, the regulator block (UP-RERA name and portal), navigation (pages with `show_in_nav`, ordered, with their public paths), public feature flags, the **current published consent texts** per purpose with their version ids (null for a purpose with no published text), active offers by placement, SEO defaults. No settings that only staff need (tracking IDs stay out until Phase 6; lead routing, email and privacy never).
3. **Projects:** `GET /public/projects` with the contract's filters (`status`, `city`, `locality`, `type`, `bhk`, `budget_min`, `budget_max`, `featured`, `sort`, `q`, paging) and `GET /public/projects/{slug}`.
   - **Search (`q`):** PostgreSQL full-text search over name, tagline, locality and city plus `pg_trgm` similarity for typos (ARCHITECTURE §14; replaces the `LIKE` in `projects/service.py`, `TODO(phase-5)`). This needs a new migration (`0007_…`) with the extension and indexes, and a working downgrade. `pg_trgm` is available on Neon; say what you checked.
   - **Project detail** includes everything the project board shows: RERA authority, registration number(s) per phase or tower, the **RERA QR image** and the regulator's website (always present on a published project, D-002); price range with `price_on_request` hiding every number; carpet area first (both units come from the stored square metres, ARCHITECTURE §6); configurations; towers/phases; amenities; specifications; location (coordinates, address, location advantages); construction updates with progress photos; payment plans; the brochure; FAQs (visible, ordered); gallery and videos with **honest labels**; the cover image; SEO fields.
   - **Hero/cover image:** decide the rule (`TODO(phase-5)` in `media/rules.py`): the pinned cover if visible and labelled, otherwise the first visible labelled gallery photo, otherwise none. Write it down as part of D-038.
4. **Properties:** `GET /public/properties` (configurations across published projects, filters and sort per the contract) and `GET /public/projects/{slug}/configurations/{config_slug}`, each with its project's RERA block and price note fields.
5. **Cities:** `GET /public/cities`: cities that have at least one published, visible project, with counts that match what the projects list returns for that city.
6. **Pages:** `GET /public/pages/{slug}` (home is slug `home`, served at `/`): published page with its visible blocks in order and **everything a block needs already resolved**, so the site renders a page with one call:
   - media items with delivery URL, width, height, alt text and honest label;
   - `project_grid`/`property_grid`: the matching items, using the same rules as the lists;
   - `faq_list`, `testimonials`, `offer_banner`: the actual visible items (an empty pick list shows nothing, D-035);
   - `stats` with source and as-of; `map` with the project's location; `lead_form` with the consent texts it needs.
   - A block whose references are all gone or hidden is left out. Legal pages return `is_draft_text` so the site can show the DRAFT marker. Landing pages return `noindex`.
7. **Posts:** `GET /public/posts` (paging, `category`, `tag`) and `GET /public/posts/{slug}` (body as FormattedText source, cover, author name only, published date, SEO).
8. **FAQs and testimonials:** `GET /public/faqs?project=` (site-wide or one published project's visible FAQs, in order) and `GET /public/testimonials?project=` (only those that can be shown: source and consent date present). Testimonials return the person's name and detail as the staff entered them for publication; nothing else about them.
9. **Redirects:** `GET /public/redirects`: active redirects (`from_path`, `to_path`, `status_code`), for the web app's middleware in 5.6. No ids or hit counts.
10. **Sitemap:** `GET /public/sitemap`: every public URL with its last-modified time: home, pages (not noindex, not drafts), posts, projects, configurations, cities, the blog index. Use the public path rules in ARCHITECTURE §6.
11. **Languages:** every endpoint takes `locale` (`en` default, `hi` ready). Translated fields come from the `translations` overlay with English fallback (D-014). The `hi` locale is only returned when flag `locale_hi` is on; otherwise English.
12. **Shapes:** public schemas are separate from the admin ones (for example `PublicPage`, `PublicPost`, `PublicFaq`) and never contain `created_by`, `updated_by`, internal notes, audit data, ids that only staff use, or anything personal. Follow the contract's names where it has them; list every addition and deviation in the report and in D-038.
13. **Caching and limits:** answers carry `Cache-Control: public, max-age=60, stale-while-revalidate=300` (the web app caches by tag in 5.2) and a strong `ETag`. A per-network rate limit suitable for a public site (say what you chose and why) answers 429 with `Retry-After`. Public routes still require the web proxy's edge key, like every route (SECURITY §1).
14. **Performance:** project detail and a page with many blocks must not run a query per item. Add tests that count queries for these two and keep them bounded.

**Out of scope:** any web page or component (5.2+), the revalidation call to the web app (5.2), redirect hit counting (5.6), lead form changes (the intake endpoints already exist), tracking and consent banner (Phase 6), the Hindi content itself.

## Rules for this task

- The contract-match test style from Phase 4 applies: each public operation keeps its method, path, operationId and the public marker.
- No new dependency is expected. `pg_trgm` and full-text search are PostgreSQL features.
- Don't change admin behaviour. If you find a bug in Phase 4 code, write it in the report; fix it only if a public endpoint can't be correct without it, and say so.
- No browser-suite changes are needed. If you run `pnpm e2e` to confirm nothing broke, keep the sign-in budget (6 per run, 15 minutes apart).

## Tests required

- For every endpoint: published items appear; drafts, archived, off-market, hidden and sample-in-production items don't (run the production cases by setting the app environment to production in the test).
- Placeholders become `null` in production and stay as they are in development.
- No staff or personal fields in any public answer (a test that walks every public schema for forbidden field names).
- Project detail always has the RERA block and QR on a published project; price fields hidden when `price_on_request`.
- Page blocks resolve correctly, drop dead references, and never widen an empty pick list.
- Search finds by name, locality and city, and with one typo.
- Translations fall back to English; `hi` ignored when `locale_hi` is off.
- Cache headers and ETag (a matching `If-None-Match` gets 304); rate limit returns 429.
- Query counts for project detail and a many-block page stay bounded.
- Migration `0007`: upgrade, downgrade, upgrade on an empty database; `alembic check` clean.
- The every-route-declares and no-redirect tests still pass.
