## Goal

Search engines can find every public page from one `sitemap.xml`. `robots.txt` keeps the whole site out of search until go-live (Phase 9), and is ready to switch on with one setting.

## Scope

1. **`sitemap.xml`** (`apps/web/src/app/sitemap.ts`, Next.js metadata route):
   - **Source:** every entry from `GET /api/v1/public/sitemap`, fetched through the data layer with the cache tag `sitemap` and the existing revalidation, never at build time only.
   - **Contents:**
     - `url` is `absoluteUrl(path)` on `SITE_URL`, never another host;
     - `lastModified` comes from `lastmod`.
     - No `priority` or `changefreq`: Google ignores them, and we don't invent values.
   - **List pages:**
     - `/`, `/projects`, `/properties` and `/contact` are in the list even if the API leaves them out (with no `lastModified` then);
     - the blog list `/blog` is in the list;
     - nothing else is added by hand.
   - **When the API fails:** the route answers with an error, not an empty sitemap (an empty one would tell crawlers the site has no pages).
2. **`robots.txt`** (`apps/web/src/app/robots.ts`):
   - **Default, which is how it ships:** `Disallow: /` for every agent, plus `Sitemap: <SITE_URL>/sitemap.xml`.
   - **Go-live switch:** `ALLOW_INDEXING=true` turns it into `Allow: /` with `Disallow: /admin` and `Disallow: /api`.
     - It only works when `APP_ENV=production` too. Staging can never be opened to crawlers by mistake.
     - Mark it `TODO(phase-9)`, and add `ALLOW_INDEXING=` (empty) to `.env.example` with a one-line comment.
   - **Out of scope:** the root layout's site-wide `noindex` meta. That is the Phase 9 gate; don't change it here.

**Out of scope:** splitting the sitemap by type or image sitemaps (a later task, if the site passes 50,000 URLs); Hindi `alternates` (Phase 8); changing the API.
