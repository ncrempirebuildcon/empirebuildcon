## Goal

The "News & guides" section of the public site. A visitor at `/blog` sees published posts, newest first, can filter by category and page through them, and opens `/blog/<slug>` to read an article. All of it comes from the 5.1 public API through the 5.2 data layer, renders on the server, and updates within seconds when staff publish a post. That last part already works through the `posts` and `post:<slug>` cache tags.

## Scope

1. **`/blog`** (`app/(site)/blog/page.tsx`):
   - **Heading and intro:** the heading and intro line from the board.
   - **Featured post:** the newest post appears as the large featured card, on page 1 with no filter only.
   - **Card grid:** cover image through `PublicImage`, with alt text and honest label; category; title; excerpt; date; read time.
     - Read time is the word count of the body ÷ 200, rounded up, minimum 1, shown as "N min read".
   - **Category chips:**
     - Built from the categories of published posts: fetch the list once at the API's maximum page size (cached by the `posts` tag; say in the report what the maximum is and what happens above it).
     - A chip is a link to `?category=<value>` with "All" first; the current chip has `aria-current`.
   - **Paging:**
     - `?page=N` with the API's page metadata.
     - Previous/Next links and page numbers as plain links (works without JavaScript); `aria-current="page"` on the current page.
   - **Empty state:** "Nothing in this category yet" with a "Show all articles" link, as on the board.
   - **Bad input:** a page number past the end, or an unknown category, shows the empty state. It never shows an error.
2. **`/blog/<slug>`** (`app/(site)/blog/[slug]/page.tsx`):
   - **Breadcrumb links:** Home / Blog / category, then the title as plain text.
   - **Header:** category, title, excerpt, author name (as the API gives it; nothing invented when it's null), date in Indian format (`12 Oct 2026`), read time.
   - **Cover image:** through `PublicImage`, with its honest label.
   - **Body:** rendered with `FormattedText` from `@empire/ui`. Never as HTML.
   - **Tags:** shown as text. There are no tag pages yet.
   - **Unknown or unpublished slug:** the site 404 (the data layer already calls `notFound()`).
3. **Share** (board: "Share · Copy link · Link copied"): one small client component, `components/public/ShareLinks.tsx`.
   - **Native share:** "Share" uses `navigator.share` when the browser has it, and is hidden otherwise.
   - **Copy link:** copies the page URL **without** query string or fragment, then shows "Link copied" in a polite live region.
   - **WhatsApp:** a link to `https://wa.me/?text=<encoded title and URL>`.
   - **No third-party scripts or SDKs.**
   - This component will be reused on project pages later, so keep it independent of posts: props `url` and `title`.
4. **SAMPLE marker:** the public post shape has no `is_sample` field, so there is no per-post badge. The site-wide "Sample data" ribbon from 5.2 (driven by `has_sample`) is the marker. Don't add the field: that's an API change, and Track A owns the API. Note it in the report as a suggestion if you think a per-post badge is needed.
5. **Page title:** set `<title>` for both pages, using the post's `seo.title` when present, otherwise the post title, with the site name. Everything else is out of scope here: description, Open Graph, canonical and structured data come in 5.6. Keep the site-wide `noindex`.
6. **Navigation:** the header's navigation comes from CMS pages, so don't edit `components/shell/`. If the owner wants a Blog link in the menu, staff can add it in the CMS later. Write this in the report.
7. **Accessibility and layout:**
   - one `h1` per page, landmarks, visible focus, 44 px targets;
   - no sideways scroll at 390 px; dates in a `<time dateTime>` element;
   - the card is one link (no nested links), with the title as its accessible name.

**Out of scope:**
- the newsletter sign-up box on the board (it's a consent form and belongs to lead forms, 5.4, Track A): leave it out entirely, with no placeholder;
- "related projects";
- metadata beyond `<title>`;
- RSS;
- tag pages;
- Hindi content.

## Tests required

- **Web unit tests:**
  - read time (empty body, short body, long body);
  - the Indian date format;
  - the category and paging link builders (they keep the other parameter, drop `page` when the category changes, and encode values);
  - `ShareLinks`: the copy-link value drops query and fragment, the WhatsApp URL is encoded, and native share is hidden without `navigator.share`.
- **Browser tests** (`qa/specs/blog.spec.ts`):
  - with seeded published posts in two categories (and one draft, which must not appear):
    - the list shows them newest first;
    - the category filter works and marks the current chip;
    - paging works with JavaScript disabled;
    - the empty state appears for an empty category;
  - the article page shows title, author, date and body text, and a `*bold*` marker renders as `<strong>`;
  - an unknown slug shows the 404 page;
  - axe on the list and the article;
  - CSP enforced with no console violations (as in the 5.2 shell tests);
  - 390 px with no sideways scroll;
  - **Revalidation:** open the article, change the post's title in the CMS, drain the outbox (as the 5.2 test does) and poll until the article shows the new title. Don't add a "before the drain" check: other specs drain the outbox in parallel, so it would be flaky (see the note at the bottom).
- Every test must be able to fail without the code it covers. In the report, say which ones you checked by breaking the code.
